# Implementation Log — Prototype Scaffold

Companion to [08_001.md](08_001.md) (the project brief). This entry records
the first playable scaffold and the decisions behind it, so future sessions
don't have to re-derive them.

## What exists now

**Autoload**
- `scripts/autoload/game_manager.gd` (`GameManager`) — stroke count, current
  checkpoint, respawn transform, level-complete state. Everything else reads
  from / signals through this.

**Player / camera**
- `scripts/player/club_controller.gd` — classic click-drag-release aim (like
  desktop mini-golf), standing in for the pen/pencil/brush "club" for now.
  Drag distance sets power; holding **Shift** swings a flatter "slide"
  (spec's "may also try to slide the eraser") instead of a lofted "whack".
  No physical club mesh/swing animation yet — see Open Questions.
- `scripts/player/camera_rig.gd` — fixed 45° downward follow camera per spec,
  lerped toward the eraser.

**Course objects**
- `scripts/objects/eraser.gd` — the ball. High-friction `PhysicsMaterial`
  (friction 2.2, rough) set directly on `Eraser.tscn`. Exposes `is_settled()`
  so the club can't strike it mid-roll, and `respawn()`.
- `scripts/objects/checkpoint.gd`, `goal_area.gd`, `floor_sensor.gd` — trigger
  volumes. `FloorSensor` covers the whole house floor; since solid course
  pieces physically block the eraser while it's on the path, any contact with
  the sensor means it fell off, matching the spec's "touches the floor →
  reset to last checkpoint" literally (contact-based, not a Y threshold).
  `eraser.gd` also keeps a Y-threshold fallback (`fall_y_threshold`) as a
  safety net against clipping through geometry.
- Collision layers: **1** = static course/floor, **2** = eraser. Trigger
  Areas mask `2` only, so they never fire on course geometry.

**Level**
- `scenes/levels/TestLevel.tscn` — a rough 11-piece blockout (book → ruler →
  stationery tray → two toy blocks → board game box → mug coaster → remote →
  junk-drawer tray → cup → goal box), X 0→8.6m, meandering in Z (0→0.6→0.1→
  −0.2) and rising/falling in Y (0.10→0.33→0.19) so it uses all three axes
  per spec. 3 checkpoints sit on pieces 3/6/9 (roughly equidistant by piece
  index, not measured arc length — see Open Questions). Background dressing
  (wall, table, bed, CRT TV) is placeholder boxes for scale context only, no
  collision.
- `scripts/levels/level_controller.gd` wires the level's Eraser/Player/Start
  together and calls `GameManager.reset_run()` on load.

**Entry point**: `scenes/Main.tscn` = `TestLevel.tscn` + `HUD.tscn`
(stroke count, checkpoint count, "COURSE COMPLETE!" message).
`project.godot` now sets this as `run/main_scene` and registers the
`GameManager` autoload.

## Decisions made without asking (flag if wrong)

- **Aim/swing input**: mouse drag-back-and-release rather than a timing-bar
  swing or physically simulated club collision. Much more robust to build
  and tune blind; a physical club is a plausible v2 (see below).
- **Scale**: built literally in meters at "small object" size (eraser ≈
  35×15×22mm, course pieces tens of cm) rather than simulating a 1:32 factor
  through camera math — the miniature feel comes from the actual geometry
  sizes plus oversized background furniture, which is simpler and matches
  how the spec describes it ("player will feel small").
- **Level geometry is a rough blockout**, hand-authored as text (no Godot
  editor available in this environment to place things visually or run the
  project to check feel/spacing). Gaps between pieces are sized generously
  to *probably* overlap, but this needs an actual playtest pass in-editor —
  treat all course transforms as provisional.

## Not built yet (explicitly out of scope for this pass)

- Physical club model/swing animation (pen/pencil/brush meshes), club
  selection/switching.
- Household-object course art — current pieces are labeled primitives
  (colored boxes), not modeled utensils/books/toys/etc.
- House interior dressing beyond 4 placeholder furniture blocks; no ceiling,
  ceiling fans, tube-lights, posters, CRT TV screen detail.
- Stroke-limit/par, main menu, level select, save/progress.
- Sound.

## Open questions for the user

1. Club feel: keep drag-release aiming, or invest in a physically swung club
   (harder to tune, more true to the brief's "hit ... like a golf club")?
2. Should the 3 checkpoints be equidistant by *arc length along the path*
   (spec says "equidistant") — current placement is only roughly even by
   piece index and should be re-measured once the path is finalized.
3. Priority order for next pass: (a) art pass on course objects, (b) house
   interior/furniture, (c) club physicality, (d) menu/UX polish?

## How to check it

No Godot binary was available in this environment to run/validate the
project — open it in the Godot 4.7 editor and hit Play on `scenes/Main.tscn`.
Hand-authored `.tscn` files may have minor issues (e.g. `load_steps` counts)
that the editor will silently fix on first save; watch the output panel for
any real script/parse errors on first open.
