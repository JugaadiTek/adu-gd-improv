# Implementation Log — Swing Rework + Headless/Local Validation

Follow-up to [08_002.md](08_002.md).

## Requested changes, implemented

- **Camera 80% closer**: `CameraRig.distance` 10.0 → 2.0 (`scripts/player/camera_rig.gd`,
  `scenes/player/Player.tscn`).
- **Swing instead of drag-pull**: `scripts/player/club_controller.gd` was
  rewritten from click-drag-release to a real swing — a "whacker" mesh
  tracks the mouse (projected onto the ground plane at ball height); crossing
  near the eraser above a speed threshold counts as a hit, with force scaled
  by swing speed. Holding **Shift** still gives the flatter "slide" instead
  of a lofted "whack".
- **Whacker selection**: press **1 / 2 / 3** to switch Pencil / Pen /
  Toothbrush, each with a different power multiplier (Pen hits hardest,
  Toothbrush softest) and its own mesh color/size.
- **Max force −80%**: `ClubController.max_power` 14.0 → 2.8.

## Bug found and fixed via headless testing

Validated in **headless Godot** (`X:\Godot_v4.7-stable_win64.exe\Godot_v4.7-stable_win64.exe --headless`,
found via a drive search since it's not on PATH — see below) using a
temporary diagnostic autoload that drove the eraser through the checkpoints,
goal, and a simulated fall, then was deleted:

- Import (`--import`) and running `Main.tscn` for up to 300 physics frames:
  clean, no script/parse errors.
- Resting physics: eraser sits stationary on the start platform for 20+
  seconds, no jitter, no falling through — course/floor collision is sound.
- Checkpoint → Checkpoint → Checkpoint → Goal progression: all correct.
- **Found**: teleporting the eraser (checkpoint/floor respawn) launched it
  to a wildly wrong position. Root cause: `Eraser` has `continuous_cd = true`
  (needed so a fast-swung, small, thin-platform-crossing ball doesn't tunnel
  through geometry), and an instantaneous `global_transform =` reposition on
  a CCD-enabled `RigidBody3D` gets read by Jolt as a high-speed sweep,
  producing a spurious collision response that flings the body.
  **Fix**: `Eraser.teleport_to()` now freezes the body for one physics frame
  around the teleport (`freeze = true` → set transform → `await
  get_tree().physics_frame` → `freeze = false`), which sidesteps the swept
  collision entirely. `respawn()` and `LevelController`'s initial placement
  both route through it now. Re-validated clean after the fix (eraser lands
  and settles correctly at the checkpoint each time).
- `Eraser.strike()` sanity-checked directly: applies the impulse, increments
  `GameManager.stroke_count`. At the new `max_power = 2.8` and the eraser's
  0.15 kg mass, a full-power hit is still ~18 m/s — worth a further pass if
  it plays too fast, but this is what "−80% force" computes to from the
  prior baseline; not second-guessed further.

it plays.
